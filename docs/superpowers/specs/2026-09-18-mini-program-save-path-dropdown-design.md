# 小程序生图保存路径下拉框与素材库写入

## 目标

小程序“选择保存路径”改为紧凑下拉选择。选项来自 PC 素材库的真实图库，并按“我的素材”和“企业共享”展示。用户选择的是一个具体、可写入的图库；生成结果完成后登记到同一个图库，因此会在 PC 端对应位置出现。

## 用户交互

1. 初始文案为“请选择保存路径”。
2. 点击字段打开原生小程序 picker，而非全屏文件夹选择层。
3. 可选项显示为完整路径：`我的素材 / 一级图库 / 二级图库` 或 `企业共享 / 一级图库 / 二级图库`。
4. 选中后字段显示完整路径，并在三个工作流草稿中复用同一保存目标。
5. 没有可写图库时，字段保持不可选并提示用户先在 PC 素材库新建可管理图库。

## 数据与权限

- 小程序沿用 `GET /api/mp/content/galleries?scope=private|enterprise` 读取目录。
- 仅暴露当前用户可以写入的目录：个人目录须归当前用户；企业共享目录须具有 PC 端的管理权限。前端只做展示过滤，后端在创建任务时必须重新校验。
- 草稿和创建任务请求携带具体图库 ID，字段仍为 `save_target_id`。
- 禁止把“我的素材”或“企业共享”这两个范围名称当成保存目标 ID；它们仅是下拉中的路径前缀。

## 后端落库

PC 图片设计生成接口增加 `save_target_id`。创建任务时验证目标分类存在、是图片图库、当前用户有写权限；将经过验证的目标分类 ID 固化到任务请求中。

Worker 成功生成每张图片后，除保存图片资产外，再创建素材库条目并关联到目标分类。企业共享目录中的条目仍遵循 PC 素材库已有的可见性与管理员权限规则。任务结果保留原有图片设计结果链接，不因素材库写入而改变。

## 兼容层

现有小程序调用的是 `/api/mp/image-design/*`，而 PC 当前实现的是 `/api/image-design/*`，且请求结构不同。因此本次需新增小程序专用的适配路由，使用小程序认证上下文调用同一图片设计服务；不能让小程序直接冒用 PC 会话接口。该适配层负责将小程序的 `save_target_id`、比例、清晰度和图片角色映射到严格的 PC 图片设计请求。

## 测试

- 小程序逻辑测试：将 PC 图库转换为可选下拉项、过滤无写权限企业目录、保留具体图库 ID 和完整显示路径。
- 小程序页面结构测试：使用 picker、无全屏保存路径选择层、提交的仍是具体 `save_target_id`。
- 后端单元测试：生成参数接受有效的 `save_target_id`，拒绝无权目标；Worker 对每张结果创建指向目标图库的素材条目。
- 现有图片设计、素材库和小程序相关回归测试必须通过。

## 非目标

- 不改变 PC 素材库的“我的素材 / 企业共享”页面设计。
- 不允许普通成员向企业共享图库写入；如业务要开放该权限，应先修改 PC 端统一权限规则，而不是在小程序绕过。
- 不迁移或修改已有素材和既有图片设计结果。
